# Admin tutorial library

All authoring content lives in the project-root `tutorial/` directory: **43 focused packages** and the retained complete workflow in `00-product-to-completed-order/`.

The Guide library at `/admin/guide` and contextual page buttons use `catalog.json`. Tutorial 01 keeps its accepted YouTube upload. Tutorials **02–43** have synchronized generation code prepared; their audio, capture, rendering and playback review remain pending.

## Authoring layout

Each remaining focused package contains:

- `production.json`: short narration sections, screen setup actions, exact focus targets and persisted-example/result checks.
- `production.md`: the readable storyboard for exactly that executable plan.
- `produce.ts`: generation entry point using the shared synchronized producer.
- `tutorial.json` and `narration.txt`: canonical scene narration, preserved for Guide content consistency.
- `fixtures.example.json`, `recording-checklist.md`: fictional data and state prerequisites.
- `record.ts` and `render.ts`: standalone synchronized capture/render entry points.
- `audio/README.md`: the section-WAV workflow; old paragraph cue examples are retained only as reference.
- `artifacts/`: ignored local audio, screenshots, receipts and rendered outputs.

`shared/produce.ts` follows tutorial 01's accepted production-build screenshot approach. Each spotlight holds throughout its corresponding measured speech. It excludes loading/navigation frames and validates encoded scene boundaries. No generated media is included in this preparation change.

## Review, upload and publication

Inspect the captured PNGs before rendering. Watch the entire output with audio, review every focus, caption, example/result and reading pause, and approve only the exact artifact hashes. Automated frame similarity checks establish image fidelity, not factual workflow acceptance.

Upload and publish only after separate authorization. The existing YouTube uploader supports resumable uploads. Put its actual video ID in `media.local.json` using `provider: "youtube"`; file hosting can use HTTPS video/poster/caption URLs instead. Publishing fills measured duration and reviewed source commit.

```bash
TUTORIAL_PUBLISH_APPROVED=true bun run tutorial:publish order-confirmation
```

Publication updates the local catalog, without committing, pushing or deploying. It checks both the canonical storyboard and synchronized production plan against the reviewed artifacts. Public catalog metadata must contain no credentials, private fixture IDs or personal data. Permission filtering does not make an unlisted YouTube video private.

## Videos and workflow diagrams in Guide

The Guide library and contextual help popup use the same metadata in `catalog.json`.

- YouTube media: `provider: "youtube"`, `videoId`, measured `durationSec`, and the full `reviewedCommit` hash. The popup uses the privacy-enhanced YouTube iframe and a permanent Watch on YouTube fallback link. It mounts only while the topic is open and does not autoplay.
- File media: keep HTTPS `videoUrl`, `posterUrl` and `captionsUrl` (optional `provider: "file"`). Existing MP4 playback remains supported.
- Optional `instructions`: short practical steps for the popup. `steps` retains canonical narration paragraphs so authoring drift checks continue to work.
- Optional `diagram`: a title, description, rows of nodes, and named edges. Nodes have stable IDs, labels, short descriptions, and an optional `step`, `decision` or `success` kind. Every edge references two node IDs; branch labels such as Yes/No explain decisions. Diagrams use theme-aware native SVG, no external renderer or dependency. Scroll horizontally on small screens when a branch needs more room.

Add diagrams when a sequence, decision or independent money/stock path benefits from a visual. Simple guides do not need a diagram. Initial flows cover product activation, stock receipt, order confirmation, delivery/completion, refunds/recovery and courier shipments.

`shared/content.ts` defines public media/diagram types and validation. Docker includes this file alongside `catalog.json`, while authoring scripts and local media stay excluded. Publishing accepts the YouTube shape in `media.local.json`; its existing exact-artifact review checks remain required for future publications.
